# 条款引用重排台（Clause Reference Rearrangement Bench）

粘贴带层级编号的合同条款，拖动调整顺序后，系统自动把「第3.2条」「第5条至第7条」等引用
**先绑定到原条款，再统一重编号并改写正文**，并排展示改动前后文本；另含
**「定义术语审校」**模块，识别合同中的定义术语及其使用，报告未定义 / 重复定义 /
歧义绑定 / 未使用定义四类问题；删除条款前还可用
**「删除影响预演」**勾选拟删条款，只读预览引用失效、术语失绑及沿反向引用的
最短受影响链，确认后再一次性套用级联删除；终审通过的草稿可在
**「🔖 生效版本」页签一键签发不可变版本**，固定当时的条款编号、引用改写与术语绑定；
同一草稿的任意两个已签发版本还可生成
**「版本差异审计」**——按原条款稳定 ID 对齐两份快照，区分正文改变 / 层级顺序调整 /
删除新增 / 仅编号改写，逐条比较引用目标、区间表达与术语绑定，并对目标删除或绑定
改变的差异从新版存活引用图计算最短受影响链（合并循环组），结果稳定排序且两版可点击定位；
审计页还可**「应用到当前草稿」**：以旧版为基线、新版为候选逐条勾选带入正文、父子顺序
层级与删除 / 恢复变更，引用改写与术语绑定在合并结果上重新计算，草稿相对旧版已改动同条
或其父级即标冲突禁覆，过期 / 阻塞 / 冲突均整体拒绝，通过后一次事务保存新修订。

## 功能

### 引用重排 / 改写

- **条款解析**：识别「第1条」「第3.2条」「第3.2.1条」「第三条」「第三条之二」以及「1.2.3」式层级编号；
  正文前的「鉴于……」等说明文字原样保留。
- **层级父子树重排**：条款按编号路径构成父子树（如 `1.1.1` 的父级是 `1.1`），换序只允许发生在
  **同一父级的兄弟之间**；拖动父条款时整棵子树一起移动，删除父条款时一并删除全部后代。
  重排后各层兄弟分别从 1 连续编号（`第1条 / 第1.1条 / 第1.1.1条……`），子条款不再被
  展平成并列的顶层编号；跨父级的非法换序会被自动归正。
- **引用绑定（先绑后改）**
  - 单条引用：`第3.2条` → 绑定原路径 `(3,2)` 对应条款，重排后改写为该条款的**完整新路径**；
  - 区间引用：`第5条至第7条`、`第3-5条`、`第4.1～4.3条` → 展开为区间内全部条款；
    仅当目标**同属一个父级且新位置末段连续**时才合并为区间，否则按新顺序拆成单条或
    同级连续区间枚举；
  - 泛指引用：`本条`、`前条`、`各条` 等不报警、不重写。
- **统一层级重编号**：以原路径为身份，按拖动后的新顺序逐层编号为
  `第1条 / 第1.1条 / 第1.1.1条……`；排序页、前后对照、草稿恢复与后端返回保持同一结果。
- **最短区间生成**：重排后区间目标若被拆散，自动按新层级位置生成最短表达——
  同父且末段连续则合并为 `第x.a条至第x.b条`（两端写完整路径），否则逐个枚举，
  单条则写成其完整新路径。
- **异常检测与定位**
  - 🟠 **无法解析**：编号格式无法识别（如「第若干条」）或目标条款不存在；
  - 🔴 **目标已删除**：引用（或区间中的部分目标）指向被删除的条款；
  - 🟣 **循环引用**：条款沿引用边互相指回（如 A→B→A，包括自引用）；
  - 点击顶部问题提示或正文中的彩色标记，即可滚动定位并闪烁对应条款。
- **并排对照**：左侧改动前原文（已删除条款置灰），右侧改动后文本（引用处彩色标记）。
- **删除影响预演（预览不改草稿）**：在排序列表中勾选一项或多项**未删除条款**后
  点击「🔍 删除影响预演」，系统先只读分析、不改任何草稿状态：
  - 勾选父条款时按现有级联规则**连同后代**纳入「拟删除集」，面板区分
    ☑ 直接勾选与 ⤷ 级联后代；
  - 比较删除前后的**引用绑定**与**定义术语绑定**，列出删除后仍存活、但
    🔴 引用失效（区间只报新增失效目标）、🟠 术语失去唯一定义（变未定义）、
    🟣 变歧义绑定或 🔵 改绑其他定义的条款；
  - 存活引用图先按**强连通分量（SCC）合并**：互相指回的存活条款（含自环）
    收缩为一个循环组，**一个循环组只生成一个影响项**，组内同根因的直接影响
    去重（术语按出现处保留并标注所在成员）；
  - 在收缩后的图上沿**反向引用**给出每个受影响条款/循环组到根因的**最短原因链**
    （循环组成员、链上节点、根因与拟删除集均可点击定位），循环组以
    「↺」标注；等长链按**文档顺序**取字典序最小者；组外条款保留到根因的
    完整最短链；
  - **过期保护**：预演面板打开期间若正文、排序或删除状态发生变化，旧结果立即
    标记过期并禁用确认，需「按当前选择重新预演」；
  - 「确认删除」一次性套用现有级联删除并刷新重排、引用改写与术语审校
    （分析失败则回滚，草稿不变）；「取消」不改变草稿。
- **示例与草稿**：一键载入内置示例（含循环引用、区间拆散、无法解析等场景）；
  草稿保存在 SQLite，可随时载入/更新/删除；编辑内容同时在浏览器 localStorage 自动暂存。

### 定义术语审校（顶部「📖 定义术语审校」页签）

- **定义识别**（术语名称须在中文引号 “ ”、「」、『』 或直引号中）：
  - `“术语”是指 / 系指 / 指 …` 为**全文定义**；
  - `本合同（本协议）所称“术语”为 / 是 …` 为**全文定义**；
  - `本条（本款）所称“术语”为 / 是 …` 为**局部定义**，作用域为**所在条款及其全部后代条款**。
- **使用识别**：中文引号中的短语一律作为候选使用；已定义名称在引号外的**无引号出现**
  同样扫描；多个名称在同一位置重叠时**最长优先**（如已定义「服务」与「服务期」，
  「服务期内」绑定「服务期」而不是「服务」），并**排除定义名称本身**（定义处引号不算使用）。
- **绑定作用域**：使用处优先绑定**最近祖先条款**上的同名局部定义，找不到再回退全文定义；
  同一作用域内有多个同名定义时**不得任选**，该使用记为「歧义绑定」并列出全部候选。
- **四类问题，均在正文高亮**：
  - 🟠 **未定义**：引号短语找不到任何可见定义（若同名局部定义只存在于其他子树会提示）；
  - 🔴 **重复定义**：同一作用域内同名定义多处；
  - 🟣 **歧义绑定**：使用处命中同一作用域的多个同名定义；
  - 🔵 **未使用定义**：定义在自身作用域内没有任何确定的使用（被歧义引用指向不算使用、
    也不再另报未使用）。
- **双向定位**：点击问题条目、正文标记或左侧术语表，可在「定义 ↔ 全部使用处」之间
  滚动定位并高亮对端。
- **以当前删除状态为准**：被删除条款（含级联删除的后代）中的定义与使用一律不参与审校；
  删除条款后重新计算，剩余条款中的使用可能变为未定义。
- **忽略项**：任何问题均可「忽略」，忽略列表随草稿保存到 SQLite、载入草稿时恢复，
  也随浏览器 localStorage 暂存；正文修改导致问题消失时，对应忽略项自动清理。

### 生效版本签发（顶部「🔖 生效版本」页签）

- **操作入口**：先解析 / 保存草稿（顶栏「保存草稿」或草稿下拉），再打开工作区
  「🔖 生效版本」页签，点击「🔖 从当前草稿签发生效版本」；有未保存修改时会先
  提示保存草稿，再以最新修订号发起签发。
- **一次操作固定四要素并重审**：签发瞬间固定**正文、条款顺序、删除状态、术语忽略项**，
  在同一请求中重新运行引用重排改写与定义术语终审。
- **零阻塞才放行**：存在 🟠 无法解析、🔴 目标已删除、🟣 循环引用，或未被忽略项
  覆盖的术语问题（未定义 / 重复定义 / 歧义绑定 / 未使用定义）时一律 **422 拒绝**，
  页面逐项列出阻塞项并可跳转「引用重排」或「术语审校」页定位，**草稿不做任何改动**。
- **修订号乐观锁**：每份草稿带单调递增的 `revision`（每次保存 +1），签发须携带
  当前修订号；若校验期间草稿被其他保存改动，则 **409 拒绝且不产生版本**，
  页面可一键载入服务器最新草稿后重试。
- **不可变版本号与摘要**：通过后在该草稿下生成 `v1、v2…` 不可变版本号，记录签发时
  的条款编号（重排结果）、逐条**引用改写结果**（原文 ⇒ 新引用 ⇒ 目标条款）与
  **术语绑定**（每处使用绑定到哪个作用域的定义），以及固定的忽略项；**后续编辑只产生
  新版本，绝不覆盖已签发版本**。
- **重复提交幂等**：相同 正文 / 顺序 / 删除 / 忽略 快照重复签发，直接返回原版本
  （不新增版本号）；仅改草稿标题不会产生新版本。
- **查看与定位**：版本列表展示编号、签发时间、条款数、改写/绑定数与对应修订号；
  点击任一版本可查看其不可变快照——左右并排的签发原文与重编号正文、引用改写清单、
  术语绑定清单与正文标注，清单与彩色标记均可点击定位到对应条款 / 定义 / 使用处。
- **兼容草稿删除**：删除草稿不会删除其已签发版本，版本仍可通过
  `GET /api/versions/{id}` 读取；草稿保存 / 载入 / localStorage 暂存与
  Docker Compose 启动方式均保持不变。

### 版本差异审计（「🔖 生效版本」页签内「版本差异审计」）

- **选两版、只对同一草稿**：从同一份草稿的已签发版本中任选**旧版 → 新版**
  两个不可变版本生成审计；审计接口只读取 `versions` 行，**草稿后续编辑或删除
  都不影响已生成的审计**（草稿被删除后版本与审计照常可用）。
- **按原条款稳定 ID 对齐两份快照**：以解析时的原路径 ID（如 `c-3-2`）为身份，
  逐条给出：
  - 🟠 **正文改变**（条款原文文本不同）；
  - 🔵 **层级 / 顺序调整**（所在层级或同父兄弟间相对名次变化）；
  - ⚪ **仅编号改写**（正文与相对顺序不变，编号仅随重排 / 其他条款删除而变）；
  - 🔴 **删除 / 新增**（原路径编号在一侧快照消失）以及**删除后恢复存活**。
- **逐条比较引用**：引用按出现处对齐（位置优先，同条款内序号兜底），区分
  引用消失 / 新增 / 改写，并分别给出每处的**目标集合变化**、**区间表达变化**
  （如 `第4条至第5条` 塌缩为 `第4条`）与引用原文变化；被移除 / 新指向的目标
  均带两版编号定位。
- **逐条比较术语绑定**：使用处按「同块同名第 k 次」对齐（可抵抗正文位移），
  比较每处使用绑定的定义（定义以「术语名 + 作用域 + 所在条款 + 同块序」语义键
  对齐，不依赖会漂移的扫描 ID），区分**绑定丢失**（旧定义在新版消失 / 所在
  条款删除）、**变歧义**与**改绑**；旧版唯一绑定的无引号使用在新版因定义移除
  而不再被扫描时也会被找回并计入。
- **最短受影响链 + 循环组合并**：对「目标已删除」或「绑定改变」的差异，在
  **新版存活引用图**上求强连通分量（含自环）并收缩为 DAG，循环组只生成一个
  影响项；在收缩图上沿**反向引用**多源 BFS 给出到根因的最短链（等长链按新版
  文档顺序取字典序最小者），链尾标注根因条款（新版被删 / 仍存活但被编辑）。
- **稳定排序与两版定位**：条款 / 引用 / 术语差异与影响行均按新版位置 +
  类型权重确定性排序；每条差异与链上节点、根因都带**旧版 / 新版编号定位**，
  页面点击任意差异行或链节点，即在下方**两版并排快照**（旧版原文、新版签发
  正文，已删除条款置灰）中同时高亮两侧条款。审计结果不写库、不占版本号。

#### 应用到当前草稿（审计页「应用到当前草稿」）

- **旧版为基线、新版为候选、当前草稿为工作副本**：在审计结果下方逐条勾选
  要带入的变更，维度独立勾选——**正文**、**父子顺序 / 层级**、
  **删除或恢复**（新版相对旧版整体新增 / 移除为**新增 / 移除**维度）；
  未勾选项一律保留当前草稿；仅编号改写无需勾选（合并后随重排自动重算）。
- **引用改写与术语绑定绝不直接拼接**：合并只搬运文本块、顺序与删除标记，
  随后在**合并后的文本、顺序、删除状态**上重新解析、级联删除、重排、
  引用改写与术语绑定审校；候选版本签发时的改写文本与绑定结果不进入草稿。
- **冲突检测（按维度禁用勾选）**：当前草稿相对旧版已改动**同一条款**
  （正文 / 层级顺序 / 删除状态任一维度）、已改动其**任一祖先条款**，
  或删除 / 移除时**子树内已有草稿改动**，相关勾选项标为冲突、禁止覆盖，
  页面在三侧快照（旧版 / 新版 / 当前草稿）中给出冲突原因与定位。
- **提交一次事务保存为新修订**：提交须携带草稿修订号与两版本快照指纹；
  修订号过期（409）、合并结果存在引用 / 术语阻塞（422）或勾选了任一冲突
  维度（422）均**整体拒绝、不写任何部分结果**；通过后在同一
  `BEGIN IMMEDIATE` 事务内保存为草稿的新 `revision`（+1），引用重排、
  术语审校、已签发版本与审计快照均不受影响。
- **页面操作**：生成审计后自动载入合并预览（也可「重新载入合并预览」），
  支持全选无冲突项、预览冲突、点击条目在三侧条款间定位；提交成功后工作区
  自动切换到合并后的草稿（引用改写与术语绑定均为重算结果）。

## 技术栈

- 后端：Python · FastAPI · SQLite（`uvicorn` 提供服务）
- 前端：原生 HTML / CSS / JavaScript（HTML5 拖拽，无任何前端构建步骤）

## 一条命令启动

```bash
docker compose up --build
```

启动后访问：

> **http://localhost:8000**

API 文档（FastAPI 自动生成）：<http://localhost:8000/docs>

停止：`Ctrl+C`；后台运行加 `-d`；清除草稿数据卷：`docker compose down -v`。

## 本地（不用 Docker）运行

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

访问 <http://localhost:8000> ，草稿数据库位于 `./data/drafts.db`。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/analyze` | 入参 `{text, order, deleted}`，返回解析、重编号、改写与异常结果 |
| POST | `/api/terms` | 入参 `{text, deleted}`，返回定义术语审校（定义、使用、四类问题与正文标记） |
| POST | `/api/delete-preview` | 入参 `{text, order, deleted, candidates}`，**只读**返回拟删除集（含级联）、删除前后绑定差异与最短原因链 |
| GET/POST | `/api/drafts` | 草稿列表（含 `revision` 与版本数） / 新建草稿（含 `term_ignores` 忽略项，返回修订号） |
| GET/PUT/DELETE | `/api/drafts/{id}` | 读取（含 `revision`） / 更新（修订号 +1 并返回新值） / 删除草稿（已签发版本保留） |
| POST | `/api/drafts/{id}/issue` | **生效版本签发**：入参 `{revision}`；阻塞项 → 422（含明细），修订号变化 → 409，重复快照返回原版本 |
| GET | `/api/drafts/{id}/versions` | 该草稿的不可变版本列表（含摘要，不含正文快照） |
| GET | `/api/versions/{id}` | 查看单个版本的完整不可变快照（正文、编号、引用改写、术语绑定） |
| POST | `/api/versions/audit` | **版本差异审计**：入参 `{old_version_id, new_version_id}`，须为同草稿的两个不同版本；返回条款 / 引用 / 术语差异、最短受影响链与两版快照 |
| POST | `/api/drafts/{id}/apply-preview` | **应用到当前草稿（只读预览）**：入参 `{old_version_id, new_version_id}`；返回逐条可勾选变更（含按维度的冲突与原因）、计数与旧版 / 新版 / 草稿三侧快照 |
| POST | `/api/drafts/{id}/apply-audit` | **应用到当前草稿（提交）**：入参 `{old_version_id, new_version_id, revision, old_fingerprint, new_fingerprint, selections}`；过期 → 409，冲突 / 阻塞 → 422（均不写部分结果），通过则一次事务保存新修订并返回合并后的草稿四要素 |
| GET | `/api/health` | 健康检查 |

签发接口的拒绝响应：

- `422`：`detail.message` 说明拒绝原因，`detail.blockers.reference_issues` 与
  `detail.blockers.term_issues`（已扣除固定忽略项）给出可定位的问题明细；
- `409`：`detail.current_revision` 为服务器最新修订号，调用方应重新载入草稿后再签。

## 生效版本签发规则速览

1. 签发以草稿当前 **正文 + 顺序 + 删除集 + 术语忽略项** 为快照，在服务端重新解析、
   级联删除、重排、引用改写与术语终审，不以前端缓存结果为准。
2. 引用侧任何 无法解析 / 目标已删除 / 循环引用 均为阻塞项；术语侧仅
   **未忽略** 的四类问题计入阻塞。有阻塞即 422 拒绝，不写库、不改草稿、不占版本号。
3. 草稿 `revision` 每次保存自增；签发在 `BEGIN IMMEDIATE` 事务锁内重读草稿，
   修订号与请求不符即 409 回滚，杜绝「校验期间草稿被改仍出版本」。
4. 版本号在同一草稿内连续分配（`v1、v2…`），版本行对
   `(draft_id, fingerprint)` 与 `(draft_id, version_no)` 均有唯一约束；
   相同快照并发 / 重复签发至多产生一行（一个新建、其余复用）。
5. 版本写入后即不可变：接口层不提供更新 / 删除版本的路由；草稿后续编辑只影响新签发。
6. 版本快照保存完整的引用分析与术语审校结果，查看页完全按签发时的数据渲染，
   不随后续草稿变化。

## 重排与改写规则速览

1. 条款以「原路径」为身份绑定引用；拖动只在同一父级的兄弟间换序，父条款移动时整棵子树
   一起移动，引用关系不丢失。
2. 重排后各层兄弟分别连续编号为 `第1条 / 第1.1条 / 第1.1.1条……`；删除父条款级联删除后代，
   剩余兄弟重新连续编号。
3. 单条引用改写为目标的完整新路径：原 `第3.2条` 随其父级变为第2条时，改写为 `第2.2条`。
4. 区间引用重写：仅当目标同父且新位置末段连续才合并。如同级目标新路径为
   `(2,1)、(2,2)、(2,3)` → `第2.1条至第2.3条`；被非同级目标隔开为
   `(2,1)、(2,3)` → `第2.1条、第2.3条`；只剩一个 → 完整单条路径。
5. 区间中部分目标已删除/不存在：剩余目标照常生成最短表达，同时给出异常提示。
6. 循环引用中的相关引用保持原文不改，标紫色并提示。

## 删除影响预演规则

1. 勾选仅来自**当前未删除条款**；父条款按既有级联规则（路径前缀）连同全部
   后代进入拟删除集，接口只做分析、不写草稿、不修改任何持久化状态。
2. 引用差异：删除前可解析且目标存活、删除后目标落入删除集的引用才算新增失效
   （区间按展开后的单条目标逐个比较，同一处引用只报一次）；删除前已失效 /
   无法解析 / 循环的引用不重复计入。
3. 术语差异：只比较删除前**唯一绑定**某定义的使用——删除后变未定义记
   「失去唯一定义」、命中多个同名定义记「变歧义」、唯一绑定的是另一存活定义
   记「改绑」；歧义改善（删除后变唯一）不报。
4. 原因链：先对删除后存活引用图求**强连通分量**并收缩为 DAG——互指条款
   （多成员 SCC）与显式自引用（自环单成员 SCC）各自作为一个循环组节点，
   **循环组只生成一个影响项**，组内同根因的引用失效去重（术语按出现处保留）；
   以含直接影响的分量为根，在收缩图上沿**反向边**多源 BFS，距离即传播跳数；
   等长链按分量首成员的文档顺序取字典序最小路径；链尾统一追加根因条款
   （被删目标 / 被移除定义所在条款，可有多个）。
5. 组外条款保留「本条款 ▸ … ▸ 根分量 ▸ 根因条款」的完整最短链；循环组的
   每个成员与全部根因均可点击定位；前置说明中的使用作为独立的「前置说明」行
   展示。
6. 预演结果与 `{正文, 顺序, 删除集, 勾选集}` 绑定；任一变化即过期，过期结果
   不能确认。确认走既有删除路径（级联删除 + 重排 + 引用改写 + 术语审校），
   取消或分析失败均不改变草稿。
